# 14. ビジネスユーザー向け: Minutes Studio の処理説明

確認日: 2026-06-10

## 1. この資料の対象

この資料は、Azure や AI の技術詳細に詳しくない方が、Minutes Studio で「音声をアップロードすると何が起きるのか」を理解するための説明です。

> **重要:** 現在の Minutes Studio は dev MVP です。顧客デモ向けの簡易アクセスキーはありますが、ユーザーごとの本格的な認証・認可はまだ完成していません。実データ、機密音声、広範な社外共有で使う前に、Microsoft Entra ID などの本番向け認証へ切り替える必要があります。

## 2. Minutes Studio がしてくれること

Minutes Studio は、録音済みの会議音声をアップロードすると、次の2つを作ります。

| 出力 | 内容 |
|---|---|
| 文字起こし | 誰が、いつ、何を話したかを時系列で確認できる発話ログ |
| 議事録 | 会議の要点、決定事項、アクションアイテム、未決事項、リスクを整理した文書 |

議事録には、できるだけ根拠となる時刻を残します。たとえば「この決定は 00:12:34 付近の発言が根拠」という形で、後から確認しやすくします。

## 3. ユーザーから見た流れ

1. ブラウザでアプリを開きます。
2. 音声または動画ファイルを選びます。
3. 必要に応じて「高速」または「高品質」の議事録生成モードを選びます。
4. アップロードして処理を開始します。
5. 画面でアップロード率、現在の処理、経過時間を確認します。
6. 文字起こしが先に準備できたら、議事録完了前でも発話ログを確認できます。
7. 処理完了後、議事録を確認します。

画面右側には、必要なときだけ開ける「仕組みガイド」があります。ここでは、標準経路、長尺時のBatch fallback、動画理解（実験）、Azure構成、データ保護方針をアプリ内で確認できます。顧客デモ中に別資料へ切り替えず、処理の裏側を説明するための補助パネルです。

## 4. 裏側で起きていること

技術名を使わずに言うと、裏側では次の処理を順番に行っています。

```text
音声を安全に預ける
-> 音声を文字起こししやすい形に整える
-> 音声全体を1回で文字起こしする
-> 話者ごとの発言と時刻を整理する
-> 文字起こし全文から議事録を作る
-> 議事録の形式をチェックする
-> 画面に表示する
```

MP4などの動画ファイルでは、映像部分は使わず音声トラックだけを取り出して処理します。音声を細かく切って並列に文字起こしする方法もありますが、Minutes Studio では通常使いません。理由は、話者ラベルの一貫性を守るためです。音声を分割すると、前半の `Speaker 1` と後半の `Speaker 1` が別人になる可能性があります。

音声がFast Transcriptionの上限を超える場合でも、Batch Transcriptionの上限内なら標準経路のまま自動で長尺向け処理へ切り替えます。これはユーザーが別モードを選ぶものではなく、アプリが入力サイズと音声長から判断します。

動画理解（実験）を選んだ場合だけ、Content Understandingで映像メモも取得します。ただし映像から見える情報を、決定事項、担当者、期限として議事録本文へ自動で混ぜることはしません。

## 5. 待ち時間の目安

処理時間は、音声の長さ、ファイルサイズ、ネットワーク、AI サービスの混雑状況で変わります。保証値ではありません。

参考として、約55分の音声では次のような計測結果がありました。

| モード | 目安 |
|---|---:|
| 高速 | 約3分弱 |
| 高品質 | 約3分強 |

長い音声ほど時間は伸びます。2時間以上の標準経路入力はBatch fallbackになるため、Fastよりかなり時間がかかる可能性があります。

## 6. 「高速」と「高品質」の違い

| モード | 使いどころ | 特徴 |
|---|---|---|
| 高速 | デモ、通常会議、まず結果を見たいとき | 待ち時間を短くしやすい |
| 高品質 | 重要会議、抜け漏れを減らしたいとき | より丁寧な議事録になりやすいが時間が長め |

どちらを選んでも、音声の文字起こしと話者分離の処理は同じです。違うのは、文字起こし後に議事録を作る AI のモードです。

## 7. 話者分離について

話者分離は、「発言者が変わったこと」を見分ける機能です。たとえば `Speaker 1`, `Speaker 2` のような匿名ラベルで表示します。

注意点:

- 実名は自動で推定しません。
- `Speaker 1 = 佐藤さん` のような紐付けは、人が確認して設定する想定です。
- 短い相づち、声が重なった場面、録音品質が悪い場面ではラベルが揺れることがあります。

## 8. 議事録生成の考え方

AI は文字起こしに書かれている内容を根拠に議事録を作ります。

守る方針:

- 文字起こしにない事実を足さない。
- 担当者が分からない場合は、無理に補わない。
- 期限が分からない場合は、無理に補わない。
- 根拠となる時刻を残す。
- speaker label から実名を推定しない。

ただし、AI が聞き間違いや要点の取りこぼしを完全に防げるわけではありません。社外共有や正式な議事録として使う前に、人が確認してください。

## 9. セキュリティとプライバシー

Minutes Studio は、次の情報をログに出さない方針です。

- 音声本文
- 文字起こし全文
- 議事録全文
- アップロードや読み取りに使う一時URL
- アクセストークンやキー

顧客デモでは、URL に加えてアクセスキーを知っている人だけが画面を開けるようにしています。ただし、このアクセスキーはデモ用の簡易ゲートであり、ユーザーごとの本格的なログイン管理ではありません。

## 10. 制限

| 項目 | 現在の扱い |
|---|---|
| 音声長 | 標準経路は4時間未満までBatch fallback候補。動画理解（実験）は120分まで |
| 標準経路の直接音声入力 | 1GB 未満。500MB超または2時間超はBatch fallback |
| 標準経路のm4a/mp4元ファイル | 4GB 未満。抽出後音声がFast上限超ならBatch fallback |
| 動画理解（実験）経路の上限 | 4GB 未満。ただしアップロード時間・解析時間・コストは増えます |
| 対応形式 | mp3, wav, m4a, mp4, ogg, webm, flac |
| リアルタイム会議 | 対象外。録音済み音声のみ |
| 話者の実名識別 | 対象外。実名は人が確認して紐付ける |
| MP4 | 標準経路では音声トラックのみ使用。動画理解（実験）では映像メモも別表示 |

## 11. よくある質問

### URLとアクセスキーを知っていれば誰でも使えますか?

顧客デモではその通りです。これはデモ用途の簡易ゲートです。本番利用では、ユーザーごとの正式なログイン管理に切り替える必要があります。

### 議事録はそのまま配布できますか?

配布前に人が確認してください。特に決定事項、担当者、期限、固有名詞は確認が必要です。

### 話者名は自動で入りますか?

入りません。`Speaker 1` などの匿名ラベルで表示し、実名は人が確認して紐付ける想定です。

### 音声や議事録はどこに保存されますか?

開発MVPでは、アプリが利用するクラウド上の保管場所に保存されます。保持期間や削除ルールは運用設定に依存します。本番利用前に、保存期間、削除方法、アクセス権限を決めてください。

### 120分を超える音声は使えますか?

標準経路では4時間未満までBatch fallback候補として受け付けます。ただしFastより時間がかかります。動画理解（実験）経路では120分超は受け付けません。

### 500MBを超えるMP4は使えますか?

標準経路でもm4a/mp4のように音声抽出するファイルなら使えます。抽出後音声がFast Transcriptionの上限を超える場合でも、Batch Transcription上限内なら自動fallbackします。動画理解（実験）経路でも4GB未満まで受け付けますが、大容量動画はアップロードと解析に時間がかかり、コストも増えるため、デモでは必要な範囲に絞った動画を推奨します。
