# ADR-001: 文字起こしは全体音声を Fast Transcription に1回投入する

日付: 2026-05-29

## 状態

採用

## 文脈

要件は、80分程度の録音済み音声ファイルを入力し、話者分離ありで議事録を短時間に生成すること。UX短縮のため、音声を短いチャンクに分けて並列文字起こしする案も考えられる。

## 決定

初期実装では、音声ファイル全体を Azure Speech in Foundry Tools の Fast Transcription に1回だけ投入し、diarization を有効にする。音声チャンク単位の並列文字起こしは実装しない。

## 理由

- 80分音声は diarization 有効時の2時間未満条件に収まる。
- 音声チャンクごとに diarization すると、`Speaker 0` がチャンク間で同じ人物を指す保証が弱くなる。
- speaker ID 統合は実装・検証コストが高い。
- 議事録生成だけを transcript チャンクで並列化すれば、UX改善と実装単純性を両立できる。

## 結果

- speaker ID の整合性を会議全体で保ちやすい。
- 文字起こし完了までは transcript を表示できない。
- UXは、直接アップロード、進捗表示、要約並列化で改善する。

## 代替案

### 音声チャンク並列文字起こし

不採用。speaker ID統合が重い。

### Batch Transcription

不採用。ピーク時遅延が大きく、即時性要件に合わない。

### LLM Speech

初期主経路では不採用。品質比較候補として残す。
